# 성능 점검 방법

카드뽑기 화면이 기기에서 끊기지 않는지(60fps 유지) 확인하는 방법입니다. 매장 85인치 TV(삼성 플립) 도입 전후 점검용으로 만들었습니다.

## 접속 주소

- 배포본: `https://jeondowon.github.io/moonbangoo/card.html` — TV 브라우저에서 바로 열 수 있습니다. `main`에 푸시해야 최신 코드가 반영됩니다.
- 로컬: `npm run dev` 후 `http://localhost:5173/card.html`

주소 끝에 아래 옵션을 붙입니다. 여러 개는 `&`로 잇습니다. 예: `card.html?fps&dpr=1`

## 주소 옵션

| 옵션 | 동작 |
|---|---|
| `?fps` | 왼쪽 아래에 1초마다 실제로 그린 프레임 수 표시. 기본값에서 바뀐 항목도 함께 표시 (예: `60 fps · dpr 1`) |
| `?quality=low` | 저사양 모드. 해상도 1배, Bloom 끔, 광택 끔 |
| `?dpr=1` | 렌더링 해상도 배율 상한 (기본 2). `1.5` 같은 값도 가능 |
| `?msaa=1` | 가장자리 안티앨리어싱(4배 MSAA) 켜기 (기본 끔) |
| `?bloom=0` | 빛 번짐(커팅 불티·잔광) 끄기 |
| `?gloss=0` | 카드·팩의 클리어코트·무지갯빛 끄기 |

`?quality=low`에 개별 옵션을 붙이면 그 항목만 덮어씁니다. 예: `?quality=low&bloom=1`은 저사양이되 Bloom은 켬.

옵션 없이 접속하면 FPS 표시 없이 기본 화질로 동작합니다. 설정 코드는 `src/gfx/quality.ts`입니다.

## 측정 순서

1. 전원 어댑터를 연결합니다. 배터리·저전력 모드에서는 GPU가 느려집니다.
2. `?fps`로 접속해 전체 흐름을 진행합니다: 팩 고르기 → 팩 커팅 → 카드 넘기기 → 요약·선택 화면.
3. 장면마다 **가장 낮은 숫자**를 기록합니다. 끊김은 최저치에서 드러납니다. 지금까지는 요약·선택 화면이 가장 무거웠습니다.
4. 60에 못 미치면 아래 순서로 옵션을 바꿔 다시 잽니다.
   1. `?fps&dpr=1`
   2. `?fps&quality=low`
   3. 원인을 좁힐 때는 `?fps&bloom=0`, `?fps&gloss=0`처럼 한 항목씩

## 결과 읽는 법

- 상한은 화면 주사율을 따릅니다. 60Hz(TV·일반 모니터) 60fps, 90Hz 90fps, 120Hz는 한 프레임씩 걸러 60fps. 즉 대부분 **60이 최고치**입니다.
- 최고치(60)에 걸리면 여유가 얼마나 남았는지는 알 수 없습니다. 약한 기기일수록 옵션을 더 낮춘 결과도 함께 봅니다.
- **화면이 아예 뜨지 않으면** 브라우저가 WebGL2를 지원하지 않는 것입니다. 옵션으로는 해결되지 않습니다.

## 매장 TV 판단 기준

| 결과 | 운영 방식 |
|---|---|
| `?fps`로 60 근처 | TV 내장 브라우저로 기본 화질 운영 |
| `dpr=1` 또는 `quality=low`에서만 60 근처 | 낮춘 화질이 괜찮으면 TV 브라우저로 운영하고 해당 옵션을 붙인 주소를 사용 |
| `quality=low`에서도 끊김, 또는 화면이 안 뜸 | 노트북을 연결해 운영 |

노트북 연결 시:

- HDMI(화면) + USB(터치) 두 선으로 연결합니다. 구매 전 판매처에 "HDMI로 연결한 PC에서 화면 터치가 되는지(터치 아웃)" 확인합니다.
- 윈도우 노트북을 권장합니다. macOS는 외부 터치스크린을 공식 지원하지 않아 별도 드라이버가 필요할 수 있습니다.
- 절전·화면 꺼짐을 끄고, 크롬 전체 화면(F11) 또는 키오스크 모드로 실행합니다.
